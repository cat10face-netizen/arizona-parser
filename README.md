# Парсер Arizona RP  Rust (мультипользовательский)

Каждый пользователь добавляет **свои cookies** (шифруются) и **свои быстрые ответы**.
Уведомления и ответы идут от его аккаунта.

## Запуск

Windows: `run.bat`  Linux/macOS: `./run.command`

Первый запуск создаёт:
- `secret.key`  ключ шифрования cookies (**не терять!**)
- `users.json`  база пользователей
- `profiles/`  изолированные профили Chrome по пользователю

## Пользователь (в VK)

| Команда | Действие |
|---|---|
| `/cookies` | пришли JSON-массив cookies, они зашифруются |
| `/quick` | список быстрых ответов |
| `/qadd текст` | добавить шаблон |
| `/qdel номер` | удалить шаблон |
| `/setsections 4041,4042` | свои разделы |
| `/mysections` | посмотреть разделы |
| `/status` | статус |
| `/cancel` | отмена |

При нажатии ** Ответить** под уведомлением бот показывает:
- кнопки с твоими быстрыми ответами
-  Свой текст  ввести вручную

## Консоль (сервер)

```
users             список пользователей
status            статистика
msg <текст>       рассылка всем
msg <id> <текст>  конкретному
importcookies [id] [файл]  импорт cookies из файла (шифруется)
quit              выход
```

## Как добавить cookies пользователю

1. Пользователь входит на форум в браузере.
2. Cookie-Editor  Export as JSON.
3. Копирует JSON и отправляет боту в VK (`/cookies`).
4. Бот шифрует и проверяет вход.

## Безопасность

- Cookies хранятся **только зашифрованными** (AES-256-GCM).
- `secret.key`  единственный ключ. Если его потерять, cookies не восстановить.
- Храни `secret.key` отдельно от `users.json` (например, в переменной окружения/секрете сервера).
- Каждый пользователь  отдельный профиль Chrome (`profiles/vk<id>`).

## Сервер (Linux)

```bash
sudo apt install -y chromium-browser   # или google-chrome
export CHROME_PATH=/usr/bin/google-chrome
./run.command
```

Для постоянной работы:
```bash
nohup ./run.command > bot.log 2>&1 &
```

## Мультипользовательская модель

- Один процесс, один VK Long Poll.
- На каждого пользователя: своя сессия браузера, свои разделы, свои шаблоны, свои уведомления.
- Общие: база `seen_items` (ключи `vk_id|url`), антидубли по каждому.

## Настройка под сервер

1. Установи Chrome/Chromium:
   ```bash
   sudo apt update && sudo apt install -y chromium
   ```
2. В `config.toml` укажи:
   ```toml
   HEADLESS = true
   CHROME_PATH = "/usr/bin/chromium"
   ```
3. Собери и запусти:
   ```bash
   cargo build --release
   nohup ./run.command > bot.log 2>&1 &
   ```

### Секреты
В git попадать **не должны**: `secret.key`, `users.json`, `cookies.json`, `state.db`, `profiles/`.
Они уже перечислены в `.gitignore`.

`secret.key`  единственный ключ к cookies. Храни в защищённом месте (например, в
секретах сервера / переменной окружения). Без него cookies не расшифровать.

### Добавить cookies пользователя
- Пользователь присылает боту `/cookies` и JSON  бот шифрует и проверяет вход.
- Или админ в консоли: `importcookies <vk_id> <путь>`.

## 12. Жалобы на администратора (контроль упоминаний)

Бот следит за разделом жалоб на администрацию и **читает первый пост каждой темы**,
ища упоминания твоих ников  **независимо от текста заголовка**.

### Настройка (`config.toml`)

```toml
ADMIN_SECTION = "https://forum.arizona-rp.com/forums/4047/"
ADMIN_NICKS = "Richard_Torenno,R.Torenno,Richard Torenno"
```

### Как работает

1. каждые `CHECK_INTERVAL` секунд открывается раздел `ADMIN_SECTION`;
2. за один проход проверяются до 12 новых тем (уже проверенные не трогаются);
3. в каждой теме читается **первый пост** (`.message-body .bbWrapper`);
4. ник ищется без учёта регистра и разделителей: `Richard_Torenno`,
   `R.Torenno`, `richard torenno`  всё это совпадение;
5. если найден  тебе в ВК приходит уведомление:
   заголовок, автор, фрагмент текста (до 600 символов) и ссылка.

### Что такое совпадение

- слово должно совпадать целиком (не часть `Richard_Torennoff`);
- допускаются разные разделители между частями ника;
- в тесте проверяются 5 случаев, включая форму жалобы
  (Игровой ник администратора: ).

## Установка на сервер: ОДНА команда

```bash
# 1) загрузи архив на сервер и распакуй
cd /opt && mkdir -p arizona-parser && cd arizona-parser
unzip arizona-parser-portable.zip

# 2) одна команда — всё само
bash install.sh
```

`install.sh` сам:
- поставит системные пакеты и **Google Chrome** (если его нет);
- поставит Rust (если нет);
- соберёт бинарник;
- выставит `HEADLESS = true`, `CHROME_PATH = ""` (авто-поиск);
- создаст systemd-сервис `arizona-parser` и **включит автозапуск**;
- запустит бота.

Проверка:
```bash
systemctl status arizona-parser
tail -f bot.log
```

Стоп / рестарт:
```bash
systemctl stop arizona-parser
systemctl restart arizona-parser
```

### Важно
- **`secret.key`** — ключ к cookies. Без него `users.json` бесполезен. Сделай бэкап.
- Не запускай бота одновременно на Windows и сервере с одним `state.db` — будут дубли.
- Chrome определяется автоматически (`/usr/bin/google-chrome`, `chromium` и т.д.).

## 13. Роли и админ-панель (ВК)

Управление — только у **основателя** (`VK_ADMIN_ID` = 731948341, фулл-доступ).

### Роли (складываются)

| Роль | Разделы |
|---|---|
| `несост` | 4041 — Жалобы на игроков (не в организациях) |
| `госсник` | 4042 — Жалобы на игроков (в организациях) |
| `гетто` | 4043 — Жалобы на бандитов |
| `маф` | 4044 — Жалобы на мафию |
| `игроки` | 4045 — Жалобы на игроков |
| `слеты` | 4048 — Опровержение со слетов |
| `смп` | 4050 — Жалобы на СМП |
| `основатель` | все разделы + админ-панель |

Настраивается в `config.toml`: `ROLE_MAP = "несост=4041;госсник=4042;..."`

### Команды основателя

| Команда | Действие |
|---|---|
| `/panel` | админ-панель с кнопками |
| `/users` | список людей: ID, роли, cookies, доступ |
| `/allow <id> [роль,роль]` | допустить человека и выдать роли |
| `/deny <id>` | забрать доступ |
| `/role <id> <роль>` | выдать роль |
| `/unrole <id> <роль>` | снять роль |
| `/roles` | список ролей и их разделов |
| `/status` | статистика |

### Для обычного пользователя

| Команда | Действие |
|---|---|
| `/whoami` | мои роли и разделы |
| `/cookies` | прислать cookies |
| `/quick`, `/qadd`, `/qdel` | быстрые ответы |
| `/cancel` | отмена |

### Как выдать доступ новому человеку

1. Человек пишет боту → бот отвечает «Нет доступа. Твой VK ID: 123456789».
2. Ты: `/allow 123456789 госсник` (можно несколько ролей: `госсник,смп`).
3. Он присылает `/cookies` → и получает уведомления только по своим разделам.
